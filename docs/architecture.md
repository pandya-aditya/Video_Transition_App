# Architecture and implementation decisions

The app runs one FastAPI process on loopback with a single background worker thread. React is compiled into static files served by the same origin; there is no second runtime service, cloud API, message broker, or vector database. SQLite WAL stores assets, durable jobs and labels. A process lock prevents two worker owners; interrupted running jobs return to the queue on restart. Heavy work is queued, not performed in the request handler.

Managed originals are SHA-256 addressed. Asset metadata includes every decoded integer PTS, rational time base, normalized presentation time, source family and detected shot boundaries. Frame access seeks to a keyframe and then resolves the requested PTS. It does not calculate a source frame using fps × timestamp. Rotation follows decoded display metadata. Imports are bounded; the local application must not be exposed as a public upload service.

DINOv2 Small provides global features and a 2×2 pooling of patch tokens. A union of global and spatial neighbors feeds ordered motion ranking. Exact matrix multiplication is enough for this small collection. Sampling is 0.5 seconds; the outgoing query may explore ±0.5 seconds. Cached incoming Farnebäck descriptors compare forward flow after B against forward flow before A. Four image quadrants retain some spatial rotation information; vectors use image dimensions and true temporal separation. Stationary pairs receive explicit handling. Motion across the actual edit is never computed.

BlazePose Lite contributes screen-space joint agreement when at least six shared joints have visibility above 0.6. Missing poses remain unavailable and the visual/motion score is used. This addition follows an observed failure: the first DINO+flow result matched a standing shooter to a gymnast on the floor. Similar backgrounds and flow were insufficient for the intended body-shape continuity. Pose is still unreliable for distant, inverted, and occluded bodies; it is not a claim of solved pose matching.

The initial combined score is 0.35 appearance + 0.40 spatial composition + 0.25 motion. When pose is available, that combination contributes 0.70 and pose 0.30. These are uncalibrated starting weights. Source-family diversification returns at most one result per family. Near-identical learned global/spatial representations are suppressed. This is not comprehensive perceptual video deduplication.

Features are keyed by source hash and a version hash containing model revisions/checksums, decode/preprocessing, spatial pooling, sampling and motion/pose definitions. Ranking weights are excluded so reweighting reuses features. Adapted checkpoint content hashes isolate their features. The model loads once per worker. A fixed positional grid is interpolated on CPU before moving DINOv2 to MPS because Torch 2.5.1 does not support the required bicubic operator on MPS; transformer inference is still accelerated.

Preview/export share an immutable edit spec: outgoing last included frame, incoming first included frame, durations, framing, resolution and renderer version. Decode uses source PTS. A 30 fps render retains the designated final A and initial B frames; intermediate frames are resampled at presentation time. The output is muted H.264/yuv420p MP4 with fast-start metadata. This is normal-speed CFR conversion, with up to roughly one output-frame of quantization. Padding preserves the full image; crop fills 16:9. Rendering uses a temporary file and atomic rename. Tests compare decoded boundary pixels against original selected frames.

Fine-tuning is deliberately small: final-block DINO normalization parameters, AdamW, regularization toward the pretrained weights, and source-disjoint validation. Human blind preferences provide pairwise supervision. Validation improvements do not automatically replace the frozen model or establish held-out perceptual improvement. The code refuses to train without real decisive labels and recorded splits. No synthetic taste labels are used.

Known engineering limits: frame-image HTTP requests decode synchronously; the media worker is a thread, not crash-isolated; queued jobs persist but inference batches are recomputed after interruption; conservative shot guards can miss dissolves; cancellation takes effect at processing boundaries; old derived cache versions are retained and count toward the disk cap. These are explicit POC tradeoffs, not production guarantees.

## Targeted collection update

Folder sync is an explicit queued action over the top level of the workspace `Videos/` directory. It does not follow symlinks or scan other folders. Managed hashes deduplicate imports; assets retain collection membership. The API's sync route uses a fixed workspace path rather than accepting arbitrary browser-supplied filesystem paths. Search filters the candidate collection before retrieval, and the review screen filters both sides of existing study pairs by the chosen collection.

Geometric descriptors are stored in separate versioned NPZ files aligned to the base embedding frame IDs. Rounded contours and circles are checked for boundary support/fit; this supplements rather than replaces learned features. Shape mode adds up to 24 geometric candidates per source to the DINO retrieval union. Where the query has detected geometric evidence, unavailable candidate evidence receives no geometric contribution (displayed as unavailable, never claimed as measured zero similarity). Where the query has no usable shape evidence, ranking falls back to composition/motion.

A bounded refinement pass examines seven incoming timestamps spanning ±0.375 seconds for up to six source families. It retains the coarse seeds, so refinement cannot lower a family's best score under the same scoring rule. All incoming windows must remain in the seed's shot and satisfy the requested context. Shared visual/flow frames decode once per batch, and a bounded in-memory feature cache accelerates repeat queries. Changing ranking weights does not invalidate learned embeddings. Result metadata identifies the ranking version separately from model and shape feature versions.

The new collection is user-provided, not a reusable public sample package. Source overlays remain in the images and can affect both visual embeddings and geometric detection. The app does not claim ownership or infer a license for those files. No uploads, weight downloads, or model training were involved in this update.
